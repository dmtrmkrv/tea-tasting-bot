# Tea tasting bot (Timeweb ready)

Новый каркас бота рассчитан на запуск в Timeweb Cloud и локальную разработку без скрытых настроек. Он использует SQLAlchemy 2.x, Alembic миграции и умеет работать как с локальным хранилищем фото, так и с S3-совместимыми сервисами.

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и заполните нужные значения.
   * Для PostgreSQL укажите `DATABASE_URL` **или** блок `POSTGRESQL_*`.
   * Если база не задана, бот автоматически переключится на SQLite (`sqlite:////app/tastings.db`).
   * Заполните `S3_*`, чтобы включить загрузку фотографий в бакет. Если переменные отсутствуют, используется локальное хранилище в `/app/photos` (путь можно изменить переменной `PHOTOS_DIR`).
2. Установите зависимости: `pip install -r requirements.txt`.
3. Запустите миграции и бота:
   ```bash
   scripts/migrate.sh
   python -m app.main
   ```
   Скрипт вызывает `python -m alembic -c alembic.ini upgrade head`, поэтому Alembic не требуется в `PATH`. Контейнерный образ
   и стартовая команда в Timeweb (`python -m alembic -c alembic.ini upgrade head && python -m app.main`) делают то же самое
   перед запуском бота.

## Что увидите в логах

* `[DB] Using: ...` — маскированный DSN подключения.
* `[DB] OK` — успешный пинг базы.
* `[S3] OK` или `[S3] WARN: ...` — результат «мягкой» проверки S3. Для локального режима появится сообщение о выбранной директории.

## Диагностика

Бот предоставляет две команды для проверки окружения:

* `/health` — краткий статус БД и S3.
* `/dbinfo` — сводка по драйверу, базе/файлу, sslmode и использованному бэкенду хранения фото. Секреты и токены при этом не выводятся.

## Деплой в Timeweb

1. Создайте ветку `rewrite/timeweb-clean` от `infra/timeweb-postgres` и задеплойте её.
2. В настройках приложения задайте необходимые переменные окружения (`BOT_TOKEN`, блок `POSTGRESQL_*` и, при необходимости, `S3_*`).
3. Убедитесь, что стартовая команда запускает миграции перед ботом. Используйте `python -m alembic -c alembic.ini upgrade head && python -m app.main`,
   чтобы не зависеть от наличия `alembic` в `PATH`.
4. После запуска проверьте логи на наличие `[DB] OK` и `[S3] ...`, затем выполните `/dbinfo` для финальной проверки.

При любой ошибке с Postgres бот переключится на SQLite, поэтому вы сможете продолжить работу, пока настраиваете облачную базу.
